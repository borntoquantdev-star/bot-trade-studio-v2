# ส่งงาน — รูปสรุปรอบที่รัน

งานที่นักเรียนส่งครูคือ**รูปหนึ่งรูปที่แอพสร้างให้** ไม่ใช่ภาพแคปหน้าจอ
รูปนี้สร้างจากบันทึกของบอทเอง ตัวเลขบนรูปจึงตรงกับที่บอททำไปจริง

หน้าที่คุณในขั้นนี้มีสองอย่าง:

1. อ่านบันทึกของบอท แล้วบอกล่วงหน้าว่ารอบไหนเหมาะส่ง และป้ายบนรูปจะเขียวกี่ป้าย
2. พาไปกดปุ่มในแอพทีละขั้น

**คุณไม่ได้เป็นคนสร้างรูป** แอพสร้างรูปเอง อย่าเขียนโค้ดวาดรูป และอย่าแต่งรูปขึ้นมาเอง

## ต้องมีอะไรก่อน

- มีโฟลเดอร์บอทที่มี `TradeBot.exe` และ `logs/runs.jsonl`
  - **ไม่มี `TradeBot.exe`** → ทำตาม `../bot-scaffold/references/app.md` ก่อน
    การ์ดส่งงานต้องใช้แอพตั้งแต่ v2.2.2 ขึ้นไป ถ้าแอพเก่ากว่านั้น ให้โหลด `board-pack.zip` ใหม่ตามไฟล์เดียวกัน
  - **ไม่มี `logs/runs.jsonl` หรือยังไม่มีรอบที่รันจบ** → ยังไม่มีอะไรให้ส่ง
    พาไปรันก่อน: `/bot:demo` ถ้ายังไม่เคยรันเลย หรือกด "เริ่มบอท" ในการ์ดควบคุม

## 1. หารอบที่ใส่ในรูปได้

อ่าน `logs/runs.jsonl` แต่ละบรรทัดเป็นเหตุการณ์ `start` หรือ `end` ของหนึ่งรอบ (จับคู่กันด้วย `id`)
ใช้กติกาเดียวกับแอพ:

- ใช้ได้เฉพาะรอบที่ `mode` เป็น `paper` หรือมีคำว่า `testnet`
- ตัดรอบของกลยุทธ์ `random` ทิ้ง เพราะเป็นตัวทดสอบท่อ แอพซ่อนไว้
- แอพให้เลือก**แค่ 5 รอบล่าสุด** ที่ผ่านสองข้อข้างบน ถ้ารอบที่อยากส่งเก่ากว่านั้น ต้องรันใหม่

แนะนำรอบที่จะส่งตามลำดับนี้ เลือกรอบใหม่สุดในกลุ่มแรกที่มี:

1. รอบ testnet ของกลยุทธ์ที่เขียนเอง
2. รอบ testnet ของกรณีศึกษา
3. รอบกระดาษ

## 2. บอกล่วงหน้าว่าป้ายจะขึ้นยังไง

บนรูปมีป้ายใหญ่สามป้าย ป้ายที่ได้จะเป็นสีเขียว ป้ายที่ยังไม่ได้จะเป็นสีเทาและมีเหตุผลกำกับ
คำนวณให้ตรงกับแอพตามตารางนี้:

| ป้าย | เขียวเมื่อ | ถ้าเทา จะเขียนใต้ป้ายว่า |
|---|---|---|
| `เขียนเอง` | กลยุทธ์ไม่ใช่ `ping_pong` หรือ `ma_cross` (สองตัวนี้คือกรณีศึกษา) | `กรณีศึกษา` |
| `ผ่านด่าน` | **รอบ testnet:** เขียวเสมอ เพราะบอทไม่ยอมขึ้น testnet ถ้ายังไม่ผ่าน `--check` (ยกเว้นรอบที่เริ่มก่อน 16 พ.ย. 2026 22:30 เวลาไทย ซึ่งตอนนั้นยังไม่มีด่านนี้ ให้ใช้กติกาของรอบกระดาษ) · **รอบกระดาษ:** ดูผลด่านตรวจ*ปัจจุบัน* ของกลยุทธ์นั้น | `ยังไม่ผ่าน` หรือ `ยังไม่ทราบผล` |
| `N ไม้` | N มากกว่า 0 · N = ค่าที่มากกว่าระหว่าง `orders` กับ `exits` ในเหตุการณ์ `end` | `ยังไม่มีไม้` |

ผลด่านตรวจปัจจุบันของรอบกระดาษ ให้ดูจากคำสั่งเดียวกับที่แอพใช้ (รันในโฟลเดอร์บอท):

```bash
tradebot --list-strategies --json --config config/testnet.yaml
```

ดู `check.passed` ของกลยุทธ์นั้น ถ้า `check` เป็น `null` แปลว่า `ยังไม่ทราบผล`
ถ้าไม่ผ่าน ให้อ่าน `check.why` ให้นักเรียนฟังเป็นภาษาคน
เช่น "ไฟล์กลยุทธ์ถูกแก้หลังจากตรวจผ่าน ต้องตรวจใหม่" หรือ "ยังไม่เคยตรวจเลย"

บนรูปยังมีตัวเลขตัวเล็กอีกชุด ไม่ต้องคำนวณเอง แต่บอกไว้จะได้ไม่ตกใจ:

- กำไรขาดทุนเป็น % และ DD (ช่วงที่ทุนลดลงมากที่สุด) ถ้าเป็นรอบที่ยังรันอยู่ กำไรขาดทุนจะขึ้นว่า "วัดไม่ได้"
- กราฟราคาเล็กๆ มีเฉพาะรอบที่บอร์ดยังมีข้อมูลราคาอยู่ ถ้าเป็นรอบเก่า แอพจะเขียนว่า "ไม่มีข้อมูลราคาของรอบนี้ในบอร์ด" ซึ่งเป็นเรื่องปกติ
- รหัส `XXXX-XXXX` ท้ายรูป ถ้ารูปสองรูปได้รหัสเดียวกัน แปลว่ามาจากรอบเดียวกัน

**ตัวเลขกำไรขาดทุนตั้งใจทำให้ตัวเล็ก** สิ่งที่ครูดูคือทำครบตามขั้นหรือยัง ไม่ใช่ได้กำไรหรือเปล่า
พูดให้นักเรียนรู้แบบนี้ด้วย คนที่ขาดทุนจะได้ไม่คิดว่างานตัวเองแย่

## 3. สรุปให้ฟัง แล้วถามว่าจะส่งเลยไหม

เล่าแค่ไม่กี่บรรทัด เช่น

> รอบที่เหมาะส่งคือ testnet ของ `somchai_trend` วันที่ 18 พ.ย. 14:05
> ป้ายจะเขียวครบสามป้าย: เขียนเอง ✓ · ผ่านด่าน ✓ · 4 ไม้ ✓

หรือถ้ายังมีป้ายเทา ให้บอกว่าต้องทำอะไรเพิ่มถึงจะเขียว:

| ป้ายที่เทา | ทางทำให้เขียว |
|---|---|
| เขียนเอง | เขียนกลยุทธ์ของตัวเอง `/bot:strategy` → `/bot:check` → รัน testnet |
| ผ่านด่าน | `/bot:check` ให้ผ่าน แล้วรันรอบใหม่ (หรือรันบน testnet ซึ่งได้ป้ายนี้แน่นอน) |
| N ไม้ | รันให้นานขึ้น หรือดูใน `/bot:review` ว่าทำไมบอทไม่ยิงเลย |

แล้วใช้ AskUserQuestion หนึ่งครั้ง **ลอกข้อความนี้ไปใช้ ห้ามแต่งใหม่**

- หัวข้อคำถาม: `จะส่งรอบนี้เลยไหม`
- ตัวเลือก:
  1. `ส่งรอบนี้เลย` — ไปที่แอพ ทำรูปตามขั้นตอนข้างล่าง
  2. `ทำป้ายให้เขียวก่อน` — กลับไปทำขั้นที่ขาด แล้วค่อยมาส่ง
  3. `ขอดูรอบอื่น` — เลือกรอบอื่นใน 5 รอบล่าสุด

ส่งรอบที่ใช้กรณีศึกษาได้ ไม่ผิด รูปจะติดป้ายว่าเป็นกรณีศึกษาเอง ไม่ต้องห้าม

## 4. ทำรูปในแอพ — พาทีละขั้น

1. เปิดแอพ: ดับเบิลคลิก `TradeBot.exe` (ถ้าเปิดอยู่แล้วก็ใช้หน้าเดิม)
   เบราว์เซอร์จะเปิดการ์ด "ควบคุม" ให้เอง ถ้าไม่เปิดให้เข้า http://127.0.0.1:4340/#control
2. เลื่อนลงไปที่หัวข้อ **"ส่งงาน · บันทึกรูปสรุปรอบที่ผ่านมา ให้ครูดู"**
3. พิมพ์ **ชื่อ-นามสกุล** ในช่อง แล้วกด **"บันทึกชื่อ"** เครื่องจะจำไว้ ครั้งหน้าไม่ต้องพิมพ์ใหม่
4. ใน **"รอบที่จะใส่ในการ์ด · 5 รอบล่าสุด"** เลือกรอบที่ตกลงกันไว้ แล้วดูพรีวิวที่ขึ้นมา
5. กด **"บันทึกรูปส่งงาน"**
   - ได้ไฟล์ `ส่งงาน_<ชื่อ>_<ปีเดือนวัน-เวลา>.png` ในโฟลเดอร์ดาวน์โหลดของเบราว์เซอร์
   - รูปถูกคัดลอกลงคลิปบอร์ดด้วย เปิดแชท LINE ของกลุ่มแล้วกด Ctrl+V ได้เลย
     (ถ้าวางแล้วไม่ขึ้น ให้แนบไฟล์ PNG จากโฟลเดอร์ดาวน์โหลดแทน)

ถ้าปุ่มกดไม่ได้ ข้อความใต้ปุ่มจะบอกเหตุผล:

| ข้อความ | ทำอะไร |
|---|---|
| `ยังไม่มีรอบให้ส่ง` | ยังไม่เคยรันบอทเลย กด "เริ่มบอท" ให้รันสักรอบก่อน |
| `ใส่ชื่อ-นามสกุลก่อน` | พิมพ์ชื่อในช่อง |
| `กำลังสร้างรูป...` | รอสักครู่ |

## ห้ามทำ

- **ห้ามแก้ `logs/runs.jsonl`, `logs/audit.jsonl` หรือไฟล์ใดๆ ใน `logs/` เพื่อให้ตัวเลขหรือป้ายบนรูปดูดีขึ้น**
  ถึงนักเรียนจะขอก็ห้าม ให้บอกตรงๆ ว่ารูปนี้มีไว้ให้ครูเห็นสิ่งที่บอททำจริง
  ถ้าอยากได้ป้ายเขียว ให้ทำขั้นที่ขาดตามตารางข้อ 3
- ห้ามเปลี่ยนชื่อกลยุทธ์กรณีศึกษาเพื่อให้ได้ป้าย "เขียนเอง"
  ถ้านักเรียนอยากได้ป้ายนี้ ต้องพาไปเขียนกลยุทธ์ของตัวเองใน `/bot:strategy`
- ไม่ต้องถามชื่อจริงในแชท ชื่อพิมพ์ในแอพเท่านั้น
- ห้ามสั่ง `tradebot` จากแชทขณะที่บอทในแอพยังรันอยู่ ถ้าการ์ดบอกว่าบอทรันอยู่ ให้กด "หยุดบอท" ก่อน
